Next steps
──────────

1. Extract the stack description this chart generated:

     kubectl get cm -n {{ include "lantern.namespace" . }} {{ .Release.Name }}-stack \
       -o jsonpath='{.data.stack\.yaml}' > stack.yaml

2. Draft specs for everything already running on the cluster:

     kubectl get deploy,statefulset,daemonset,cronjob -A -o yaml \
       | lantern discover - -team unassigned > services.yaml

3. Read services.yaml. Every value in it was inferred; lines marked REVIEW are
   guesses that most likely need editing. Fix the teams especially — alerts
   cannot be routed without them.

4. Compile and apply:

     lantern synth -stack stack.yaml services.yaml | kubectl apply -f -

{{ if (index .Values "kube-prometheus-stack" "enabled") -}}
5. Open Grafana:

     kubectl port-forward -n {{ include "lantern.namespace" . }} svc/{{ .Release.Name }}-grafana 3000:80

   You will find the cluster and node dashboards that kube-prometheus-stack
   ships, a per-service Lantern dashboard for each ServiceObservability
   (burn-rate + error-budget panels, plus Logs and Traces panels that report
   why they're empty if their datasource isn't wired up), and the SLO
   burn-rate alerts Lantern generated under Alerting.

   Per-service dashboards need target.metricsPort set correctly (or a real
   named "metrics" port on the target Service) before their panels show
   real data — see the REVIEW markers services.yaml gives you in step 3.
